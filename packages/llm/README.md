# LLM request accounting

The client uses provider-reported `usage.cost` in USD. It accepts finite, nonnegative numeric costs, including zero; it does not estimate prices from token counts or model names. `getUsage().costUsd` is the sum of known costs; `getUsage().costKnown === false` explicitly marks an incomplete bill after an unmetered response or ambiguous failure. Reports/UI must label this value as known charges, with total spend unknown. Traces retain known token usage and flag responses with missing/invalid cost.

Every request, including format fallback and schema repair, sends `max_tokens` from the positive-integer `maxOutputTokens` setting (default 2048; environment `LLM_MAX_OUTPUT_TOKENS`). OpenRouter documents this bound in its [request parameters](https://openrouter.ai/docs/api-reference/parameters). Providers must support that parameter; direct OpenAI o-series endpoints require `max_completion_tokens` instead and are not compatible with this request format. The token bound limits completion length, not dollar charges, tool costs or account-wide spend.

Requests are serialized so each response is accounted for before the next dispatch. A missing, negative, nonnumeric or nonfinite cost rejects the current result and blocks queued calls, repair attempts and later calls for that audit. Ambiguous transport/provider failures also stop the audit because they may have been billed. SDK transport retries are disabled. `maxRetries` controls only metered JSON/schema repair attempts (zero disables repairs); `concurrency` remains accepted for configuration compatibility, but effective metered dispatch concurrency is always one for cost safety. A provider's explicit rejection of structured-output support can still trigger JSON-object fallback; schema repair can run only after a response with a known cost and remaining budget.

`resetAuditMeter()` starts a fresh accounting period only when no calls are active or queued; otherwise it throws. Reuse one configured client per audit. Separate clients/processes do not share this meter.

`maxSpendPerAuditUsd` stops subsequent dispatch once the known cost reaches the limit. A single in-flight request can exceed the remaining budget, because its price is known only after completion. This is not a hard billing cap. Use provider-side spending limits as well: OpenRouter documents an optional per-key USD limit and BYOK inclusion policy in its [API-key creation reference](https://openrouter.ai/docs/api/api-reference/api-keys/create-keys). Confirm the configured provider's enforcement rules; the client cannot impose account-wide limits.

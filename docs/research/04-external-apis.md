# External API integration spec (research, 2026-10-20)

For the product, model these as optional connectors behind provider interfaces. Never imply that submission means indexing, that a third-party index equals Google, or that sampled AI answers prove total visibility. Costs and model IDs change; refresh vendor catalog/pricing before launch and keep budgets/caps configurable.

## 1. Google Search Console (GSC)

**Auth/property.** Use server-side OAuth 2.0 authorization-code flow for the site owner, request only `https://www.googleapis.com/auth/webmasters.readonly` by default; request `https://www.googleapis.com/auth/webmasters` only if the user explicitly enables sitemap writes. User must grant access to a verified GSC property; property URL must match exactly (URL-prefix vs `sc-domain:`). GSC API calls require an authenticated user; service-account credentials can technically authenticate, but a service account is not automatically a property owner: user must add its service-account email to the GSC property. OAuth is preferable for broad consumer self-serve. Encrypt refresh tokens, restrict access, support disconnect/revoke, never send tokens to browser/logs. [OAuth/scopes](https://developers.google.com/webmaster-tools/v1/how-tos/authorizing) · [Prerequisites](https://developers.google.com/webmaster-tools/v1/prereqs)

**Endpoints/minimal shapes.** Base `https://www.googleapis.com/webmasters/v3`.

- Search traffic: `POST /sites/{urlEncodedProperty}/searchAnalytics/query` body `{startDate,endDate,dimensions?:["query","page","country","device"],type?:"web",rowLimit?:25000,startRow?:0}`; response `{rows:[{keys:[...],clicks,impressions,ctr,position}]}`. Dates required; query/page data may be omitted/anonymized and result has a data-row cap.
- URL Inspection: `POST https://searchconsole.googleapis.com/v1/urlInspection/index:inspect` body `{inspectionUrl,siteUrl,languageCode?}`. Response has `inspectionResult.indexStatusResult` (coverage/indexing verdict, canonical, crawl), `richResultsResult`, `mobileUsabilityResult` (field coverage varies; mobile usability reporting may be absent/deprecated in live response). Treat absent as unknown, not pass. [Reference](https://developers.google.com/webmaster-tools/v1/urlInspection.index/inspect)
- Sitemaps: `GET /sites/{site}/sitemaps`, `GET /sites/{site}/sitemaps/{feedpath}`, `PUT` same path to submit, `DELETE` to remove. [API reference](https://developers.google.com/webmaster-tools/v1/api_reference_index)

**Quotas.** Google publishes Search Analytics 1,200 QPM per-site and per-user; project 40,000 QPM/30M QPD. URL Inspection 600 QPM/2,000 QPD per-site; project 15,000 QPM/10M QPD. Search Analytics also has query-load quotas; 25K rows/page and max 50K rows/day/search type. Respect 429/quota errors with exponential backoff + jitter, cache results, schedule deltas, avoid repeated broad queries. Quotas can vary; console quota page is authoritative. [Limits](https://developers.google.com/webmaster-tools/limits) · [Data paging](https://developers.google.com/webmaster-tools/v1/how-tos/all-your-data)

**Client.** `googleapis` offers typed services and OAuth integration; minimal dependency alternative is raw `fetch` with bearer token, explicit URL encoding, schema validation, and retry handling. For this modest surface, raw fetch is easy to isolate; use `googleapis` if already installed or wanting generated types. Do not use an API key as user authorization.

## 2. Bing Webmaster Tools + IndexNow

**Bing auth/site.** REST APIs support OAuth 2.0 (recommended by Microsoft) or a user-level API key; the user must own/verify each site. API key is generated in Bing Webmaster Tools and grants access across that user's verified sites, so treat it as a high-value credential. Prefer OAuth access/refresh tokens for customer connections. REST docs now exist; legacy SOAP/POX is scheduled for retirement 2026-08-31, so do not build on it. [Access methods](https://learn.microsoft.com/en-us/bingwebmaster/getting-access) · [REST overview / retirement](https://learn.microsoft.com/en-us/bingwebmaster/)

**Endpoint surface.** Microsoft documentation presents REST API reference and legacy examples; verify current exact REST route/version from the live API reference before shipping (do not hard-code the older `.svc/json` interface). Capabilities documented include site list/details, URL inspection/index info, rank & traffic stats, crawl stats/issues, sitemaps and URL submissions. Typical query arguments are `siteUrl`, URL, and date range; normalize results into `{indexed?,lastCrawled?,crawlErrors?,clicks?,impressions?}` with unknown fields allowed. Microsoft’s older JSON example is `POST https://www.bing.com/webmaster/api.svc/json/SubmitUrl` body `{siteUrl,url}`; use only as reference, not the new REST transport. [API docs](https://learn.microsoft.com/en-us/bingwebmaster/) · [Protocol guidance](https://learn.microsoft.com/en-us/bingwebmaster/api-protocols)

**IndexNow.** Separate from Webmaster reporting and does not require Bing OAuth. Generate random 8–128 character hex/hyphen key; publish exact UTF-8 key at `https://host/{key}.txt` (or provide `keyLocation`). Submit updates/deletes to one participating endpoint; global endpoint `POST https://api.indexnow.org/indexnow`, JSON `{host,key,keyLocation?,urlList:[...]}`; maximum 10,000 URLs/request. A key file's path scopes allowed URLs. A successful notification is not an indexing guarantee; IndexNow shares among participating engines and does not submit to Google. Only submit URLs on behalf of a verified/authorized site owner. [Protocol](https://www.indexnow.org/documentation) · [FAQ / batch limit](https://www.indexnow.org/faq)

**Limits/cost.** APIs and IndexNow have no general per-request price in cited docs; enforce conservative per-account throttling, honor Retry-After and service errors, batch IndexNow below 10,000, and confirm live per-operation limits in Microsoft portal/reference. No Bing Web Search API fallback: Microsoft retired Bing Search APIs on 2025-08-11; Azure Grounding with Bing Search is a separate product, not a public search-results API. [Retirement notice](https://learn.microsoft.com/en-us/lifecycle/announcements/bing-search-api-retirement)

## 3. Index-presence checks without customer credentials

There is no dependable unauthenticated Google index-status API. `site:example.com/path` queries are rough, non-exhaustive hints, not index counts/status; automated scraping of consumer search pages is fragile and may violate site terms, access controls, or trigger blocking. Do not scrape Google/Bing SERP HTML or present `site:` absence as definitive.

**Recommended pluggable provider: Brave Search API** (`GET https://api.search.brave.com/res/v1/web/search?q=...`, header `X-Subscription-Token`; inspect `web.results[].url`). Independent search index gives a lawful API route, but measures presence in Brave, not Google. Official current pricing lists Search at $5/1,000 requests, $5 monthly credits and 50 QPS; key belongs server-side. [API/auth/pricing](https://brave.com/search/api/) · [Authentication](https://api-dashboard.search.brave.com/documentation/guides/authentication)

Alternatives: Bing Web Search API is retired (above). SerpAPI/Serper are paid SERP vendors; DataForSEO offers SERP/AI datasets with pay-as-you-go product-specific pricing. Compare current price, target engine/geo fidelity, result retention rights, and terms at procurement; no fixed comparative cost here because prices and endpoint units change. [DataForSEO pricing](https://dataforseo.com/pricing-list) · [SerpAPI pricing](https://serpapi.com/pricing) · [Serper pricing](https://serper.dev/pricing)

Store provider, engine, query, locale, timestamp, and matched URL as evidence; show a confidence/source label and let users rerun. Keep adapter interface e.g. `checkPresence({url, locale}): Promise<{provider, found, matchedUrl?, checkedAt}>`.

## 4. OpenRouter for audit LLMs

**SDK/auth.** OpenAI JS SDK works with `baseURL: "https://openrouter.ai/api/v1"`, server-side `OPENROUTER_API_KEY`, optional `HTTP-Referer` and `X-Title` headers. Never expose key in frontend. POST `/chat/completions` with `{model,messages,...}`; response follows OpenAI chat shape, with model/provider and usage (including cost where returned; endpoint `/api/v1/generation?id=...` can retrieve generation details). Validate and persist only minimum needed usage metadata. [OpenAI SDK compatibility](https://openrouter.ai/docs/quickstart) · [API reference](https://openrouter.ai/docs/api-reference/overview)

**Structured output.** Send `response_format:{type:"json_schema",json_schema:{name,strict:true,schema}}`; model/provider support varies. Check model metadata/support in live catalog and use provider routing `require_parameters:true` when the format is mandatory; still validate JSON and handle refusal/truncation. Do not silently assume all models honor schema. [Structured outputs](https://openrouter.ai/docs/features/structured-outputs) · [Provider routing](https://openrouter.ai/docs/guides/routing/provider-selection)

**Web search/citations.** `:online` suffix (e.g. `perplexity/sonar-pro:online`) or `plugins:[{id:"web",...}]` enables search on supported models. Results may include citations/annotations and search metadata; preserve URLs and quote only small evidence. OpenRouter web search incurs model token charges plus search-provider charges (current docs list per-search cost, configurable engine/context); confirm current rate in settings/docs before enabling. Search is not a substitute for querying actual ChatGPT or Google user interfaces. [Web search tool](https://openrouter.ai/tool/web-search/)

**Routing, limits, spend.** Set `models:[primary,fallback,...]` for model fallback; provider failover is automatic. Use budgeted max tokens, bounded retries, account/key spend limits, concurrency controls and 429 backoff. OpenRouter/model providers have varying rate limits; no single global RPM applies—read errors and account/model/provider limits. Record `usage`, `model`, response ID and reported cost; pricing is per model/provider and can change. [Fallback/latency](https://openrouter.ai/docs/features/latency-and-performance) · [Models/prices live catalog](https://openrouter.ai/models)

**Recommended starting model IDs (live catalog IDs as observed 2026-10-20; verify availability/price/structured-output and search flags at runtime):**

- Cheap LLM judge: `deepseek/deepseek-v3.2` (catalog lists ~$0.2088/M input, $0.3096/M output; JSON schema support). Good for rubric scoring; benchmark against a human-labeled audit set.
- Synthesis: `google/gemini-3.8-flash` (current Gemini Flash family ID shown in catalog; confirm exact current cost/schema capability before pinning; fallback `deepseek/deepseek-v3.2`).
- AI visibility probe with citations: `perplexity/sonar-pro:online` (or `perplexity/sonar:online` for lower-cost shallow probes). Verify live catalog IDs and citation field behavior; keep answer and citations as sampled observations, not coverage proof. Perplexity Sonar model pages expose provider/model pricing and search grounding; OpenRouter charges routed model/search costs. [Gemini current alias](https://openrouter.ai/google/gemini-flash) · [DeepSeek V3.2](https://openrouter.ai/deepseek/deepseek-v3.2) · [Perplexity models](https://openrouter.ai/perplexity)

## 5. AI search visibility measurement

No public first-party endpoint gives a universal “visibility in ChatGPT Search / Google AI Overviews / Perplexity” score. GSC reports conventional Google Search performance and URL Inspection, not AI Overview citations as a separate dependable per-prompt feed. OpenRouter online models can probe answers/citations but measure one model, prompt, region, time, and retrieval path only.

For scalable measurement, offer two clearly distinct modes: (1) **first-party** GSC/Bing performance/index data for connected properties; (2) **sampled AI response monitoring** using a pinned model+web plugin (OpenRouter/Perplexity) or paid SERP/AI data APIs. DataForSEO AI Optimization advertises LLM responses/mentions and Google AI Overview data; its AI Optimization API includes prompt/LLM mention datasets, while SERP AI Overview endpoint can capture SERP feature results. These are third-party observations, not official platform analytics; disclose coverage, locale, refresh cadence, and per-call cost, and sample a saved prompt set repeatedly. [DataForSEO AI Optimization](https://dataforseo.com/ai-optimization-api) · [AI Overview SERP endpoint](https://docs.dataforseo.com/v3/serp-ai_summary/) · [LLM Responses pricing](https://dataforseo.com/pricing/ai-optimization/llm-responses)

## Security and product rules

- Keep OAuth refresh tokens, GSC/Bing API keys, Brave/DataForSEO/SerpAPI keys, and OpenRouter keys encrypted at rest; decrypt only in server-side connector workers. Redact Authorization, API keys, URL query credentials, and prompts containing customer data from logs.
- Request read-only scopes by default; sitemap write/URL submission requires an explicit user action and verified ownership. Support disconnect and credential rotation; isolate credentials per tenant and enforce tenant checks before connector calls.
- Treat every provider response/snippet/AI citation as untrusted input. Escape output, enforce outbound URL/SSRF protections if fetching cited URLs, and bound response sizes, concurrency, retries, and spend.
- Cache by tenant/property/query/date/locale within provider terms; label freshness. Search-result storage/redistribution rights vary (Brave explicitly limits storage rights by plan), so retain only permitted fields and duration.
